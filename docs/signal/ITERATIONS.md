# Итерации до полного клиента

Цель: стабильный, быстрый, приватный и безопасный клиент Signal с функциями настольного и мобильного Signal (кроме невозможного на платформе: FCM, Google Pay), регистрацией по номеру, без кода Telegram API и Telegram-функций, с Tauri-версией для macOS, Windows и Linux и собственной темой в стиле Signal.

Каждая итерация: запуск субагентов → ожидание → проверка (tsc, ESLint, CSS, браузер, живой тестовый аккаунт) → исправления → план следующей → запуск. После каждого слияния изменения пушатся в рабочую ветку и `master`.

## 1. Основа (идёт)
- Вычищение сетевых обращений к Telegram, CSP только на свой origin и туннель.
- Перенос истории при привязке (link-and-sync).
- HTTP/2 для storage, групп и CDN; исправление приёма и записи больших объёмов в TLS-клиенте WASM.
- Этап 1: удаление функций Telegram (платные функции, проверки Premium, перевод, AI, викторины, теги, chatlists, custom emoji, Instant View, карты, облачный пароль, модалки, каналы, форумы, боты, Mini Apps).
- Интерфейс: эмодзи в реакциях, плашки удалённых сообщений, галочки доставки и прочтения, цвета аватаров, свой профиль.

## 2. Без Telegram и десктоп
- Удаление GramJS и Telegram API (этап 3): сделано (2026-11-21), воркер, типы методов и действия только на Signal; строки локализации внутри сборки. Осталось: русская локализация (в сборке только английский `fallback.strings`) и вырезание вызовов удалённых методов из действий UI (`FRICTION_LOG.md`).
- Tauri: транспорт через команды и IPC-каналы на библиотеке туннеля, трей и системные уведомления, новое имя и иконки, обновления с наших релизов, сборки для macOS, Windows и Linux в CI.
  - Сделано (`tauri/README.md`): приложение TeleSignal (`org.telesignal.desktop`) со встроенным фронтендом; нативный транспорт (`signal_connect`, `signal_send`, `signal_ack`, `signal_close`) на `proxy/src/lib.rs` с мостом воркер -> страница через `MessagePort`; настройка прокси переключает на туннель WebSocket; трей и счётчик, скрытие окна при закрытии, уведомления через плагин, схема `sgnl`, обновления только из конфигурации сборки; `.github/workflows/desktop.yml` (macOS arm64 и x64, Windows x64, Linux deb и AppImage). Проверено: сборка Linux (deb, AppImage); тесты транспорта; TLS из WASM через подставной IPC до `chat.signal.org` и `cdn.signal.org` (загрузка больше окна приёма, отказ по SNI); под Xvfb приложение показывает QR привязки, полученный от сервера через нативный транспорт, и принимает ссылку `sgnl:` от второго запуска.
  - Осталось: проверка сборок macOS и Windows в CI и подписи, автозапуск (новая зависимость `tauri-plugin-autostart`).
- Уведомления в браузере при открытой вкладке.

## 3. Группы и синхронизация
- Управление группами v2: создание, название, описание, аватар, участники, админы, права, ссылки-приглашения с одобрением, заявки, баны, выход и завершение группы.
- Запись в storage service: архив, закрепы, mute, «непрочитанное», контакты, блокировки, настройки, папки.
- Синхронизация `deleteForMe`, запросы на переписку (принять, удалить, заблокировать, спам), блокировка.

## 4. Регистрация и основное устройство
- Регистрация по номеру: verification session, captcha, SMS и голосовой код, атрибуты аккаунта, ключи, профиль.
- PIN и SVR2/SVR3 (attestation: патч `attest` для WASM), registration lock, смена номера.
- Поиск по номеру через CDSI (attestation).
- Привязка других устройств к основному, управление связанными устройствами.

## 5. Медиа и контент
- Истории: просмотр, отправка медиа и текста, My Story, списки рассылки, групповые истории, ответы, реакции, просмотры.
- Стикерпаки: установка, отправка, синхронизация; превью ссылок через contentproxy; отправка контактов; интерфейс опросов и закрепов; альбомы из нескольких вложений.

## 6. Профиль и приватность
- Редактирование профиля и аватара, юзернейм (создание, смена, ссылка, QR), видимость и поиск по номеру.
- Safety numbers, key transparency, проверка ключей, настройки приватности, исчезающие сообщения по умолчанию.

## 7. Звонки
- 1:1 и групповые звонки, call links: в Tauri через нативный стек RingRTC, в браузере после отдельного исследования медиастека (`docs/signal/CALLS_RESEARCH.md`).

## 8. Внешний вид
- Тема в стиле Signal (светлая и тёмная), цвета чатов и обои Signal, профили уведомлений, доступность, локализация EN/RU.

## 9. Резервные копии и остальное
- Secure backups, attachment backfill, платежи MobileCoin (показ и отправка, если возможно на платформе), бейджи.

## 10. Надёжность
- Аудит безопасности, фаззинг парсеров, шифрование локальной базы код-паролем, профилирование скорости, консоль без ошибок, сквозные тесты на живом тестовом аккаунте, документация развёртывания.

## 11. Второй клиент на Telegram Web K (идёт)
- Telegram Web K (`morethanwords/tweb`, GPL-3.0-only) лежит в `webk/`; коммит, исключённые файлы, лицензия и локальные изменения — в `webk/NOTICE.md`. GPL-3.0-only совместима с GPL-3.0-or-later остального репозитория и с AGPL-3.0 libsignal (раздел 13 GPL-3.0).
- Туннель `proxy/` общий для обоих клиентов.
- Движок не скопирован: Web K в своём воркере (`SharedWorker`) запускает тот же провайдер Web A `src/api/signal` над движком `src/lib/signal` (псевдоним `@signal-app/provider`). Менеджеры Web K не говорят с Telegram: `ApiManager.invokeApi` передаёт методы `appSignalManager` (`webk/src/lib/appManagers/appSignalManager.ts`), который отвечает данными провайдера в форме Telegram (`webk/src/lib/signal/builders.ts`) и превращает обновления провайдера в обновления Telegram. MTProto удалён: `src/lib/mtproto` (сеть, авторизация, транспорты, DC, схема), `networkerFactory`, методы MTProto криптоворкера (AES-IGE, RSA, разложение) и расшифровка push-уведомлений Telegram; `apiManager` только передаёт вызовы адаптеру. Состояние соединения приходит из `updateConnectionState` провайдера, время сервера — из `updateServerTimeOffset` (`appManagers/timeManager.ts`), переподключение — `reconnectNow` провайдера. Типы слоя (`layer.d.ts`) остаются: менеджеры говорят в форме Telegram. Криптоворкер остаётся: он шифрует хранилища под паролем и кэш, распаковывает стикеры. Воркер в сборке стал меньше: 2,12 → 1,55 МБ (модуль с чанками), 2,51 → 1,92 МБ (одним файлом).
- Сборка: один origin. `npm run dev` поднимает оба Vite-сервера на одном порту (`/a/` — Web A, `/k/` проксируется на сервер Web K). `npm run build:production` (`dev/build.ts`) собирает Web A в `dist/a`, Web K в `dist/k` и корневую страницу, которая открывает фронтенд по умолчанию; его задаёт одна константа `DEFAULT_FRONTEND_PATH` в `plugins/frontends.ts` (сейчас `a/`, пока Web K не полон; цель — `k/`), ей следуют nginx, Tauri и dev-сервер. Tauri стартует с корневой страницы и пускает в IPC обе. Переключатель: «Switch to A version» в меню Web K, «Switch to K version» в меню «More» Web A; смена URL работает так же.
- Хранение одно: аккаунт, ключи, сообщения, вложения и настройки Signal — в хранилищах движка, имена по `getEngineStoreName`; метка слота аккаунта (`account1` с `isLinked`, `userId` в id Web A) общая. Web K сдвигает id пиров на `1e10`, чтобы они не совпадали с его папками и служебными id, и переводит их обратно на границе.
- Один движок на слот: `startClient` берёт Web Lock (`src/lib/signal/engineOwnership.ts`) и забирает его у движка, который его держит, — тот останавливается. Вкладка другого фронтенда показывает экран «неактивно» (общий канал `tgweb`), по клику забирает движок обратно.
- Тема Web K: синий Signal (`#2c6bed`) и однотонный фон без узора Telegram в светлой и тёмной темах, QR-код без логотипа в центре, нейтральные иконки и логотип (облачко), строки интерфейса называют TeleSignal.
- `npm run check:hosts` проверяет исходники Web A и собранный бандл Web K; ссылки Telegram-функций, которые Web K ещё строит, ведут на зарезервированные имена `.invalid`.
- Сообщения (Web K): реакции (показ с авторами, добавление, смена и снятие, список тех, кто отреагировал), ответы с цитатой и переход к исходному сообщению, правка (сутки, «изменено»), удаление у себя и у всех (сутки, только свои сообщения, у собеседника только «у себя»), пересылка (одна копия: каждая получает свой `random_id` до сохранения в движке), поиск по тексту в чате и по всем чатам с подкачкой страниц, счётчиком совпадений и фильтром по отправителю, поиск пользователя по имени кнопкой «Find by username» (сервер спрашивают по нажатию и только для имени Signal вида `nickname.NN`), меню без пунктов Telegram, форматирование в поле ввода без подчёркивания, цитат и ссылок. Черновики Web K хранятся в его хранилище и переживают перезагрузку (проверено), с Web A и другими устройствами не синхронизируются. Выделение нескольких сообщений с удалением и пересылкой, переход к первому непрочитанному работают.
- Опросы в Web K: показ с результатами и голосами, голосование, отзыв голоса и повторный голос (проверено на демо-опросе), список проголосовавших (`messages.getPollVotes`), завершение своего опроса (`messages.editMessage` с закрытым опросом → `closePoll`), создание опроса в группах с пределами Signal (2–10 вариантов, вопрос и варианты до 100 символов, Signal Desktop `ts/types/Polls.dom.ts`) и одной настройкой — несколько ответов; описание, медиа, викторина, срок и прочие настройки Telegram убраны.
- View once в обоих клиентах: неоткрытое фото или видео — строка «View-once photo» с кнопкой View. Нажатие загружает медиа, отмечает сообщение просмотренным и только потом показывает загруженную копию (Signal Desktop `showLightboxForViewOnceMedia`), так что закрытая с открытым просмотром вкладка не оставляет его непросмотренным; второе нажатие ничего не открывает. Движок при просмотре удаляет вложения из `ts-signal-attachments` (`eraseMessageContents` в `markViewOnceMessageViewed`), провайдер забывает свою копию в памяти. Web K не пишет медиа view-once в `cachedFiles` и `cachedStreamChunks`: копия — object URL в хранилище миниатюр воркера, закрытие просмотра его отзывает (проверено: кэши до и после просмотра без него). Переслать, сохранить и скопировать его нельзя (`noforwards`).
- Звонки в Web K: пункт «Calls» открывает журнал звонков Signal (`fetchCallLog`), открытие отмечает звонки просмотренными (`markCallLogSeen`), «Delete all calls» очищает журнал (`clearCallLog`); групповые звонки и звонки без уведомления в чате тоже в журнале, их строка открывает чат в конце; удаления по одному звонку и «для всех» нет, как в Signal. Кнопки звонков (шапка, профиль, перезвонить, конференции, «Speakers and Camera») скрыты: звонить не умеет ни один клиент. Уведомления о звонках в чатах — служебные строки, как в Web A.
- Меню чата Web K совпадает с Web A: Auto-delete, Mute, Select Messages, Block/Delete или Leave Group; «Share contact», «Set Wallpaper» и «Report» убраны. Карточку контакта отправляют пункт «Contact» меню вложений (как в Web A, `inputMediaContact` → `sendMessage` с `contact`) и «Share contact» в меню профиля контакта, в том числе без номера: карточка Signal несёт ACI (проверено на демо: карточка появляется в чате, отправка без сервера помечается неудачной). Карточки превью ссылок у полученных сообщений показываются из данных сообщения (ветка медиа), адрес не загружается.
- Закреплённые сообщения в обоих клиентах: движок отправляет `pinMessage`/`unpinMessage` (Signal Desktop `sendPinMessage`), хранит три последних закрепа, принимает закрепы только от тех, кто может менять группу (и в группах «только администраторы пишут», как Signal Desktop), добавляет в ленту уведомление «закрепил сообщение» при отправке и получении, снимает истёкшие закрепы по таймеру; провайдер отвечает на `fetchPinnedMessages`, `pinMessage`, `unpinAllMessages` и шлёт `updatePinnedIds`. Web K: пункты Pin/Unpin, закреплённая полоса, снятие всех; Web A: диалог без «только у меня». В демо отправка не проходит (нет сервера) и закреп откатывается; полоса проверена на закрепах, записанных в базу.
- Информация о сообщении в Web K: пункт Info у исходящих, получатели по статусам (не отправлено, просмотрено, прочитано, доставлено, отправлено, ожидает) из `fetchMessageSendDetails`.
- Упоминания: автодополнение участников группы работает; Web K отправлял упоминание как текст (`inputMessageEntityMentionName` с input user), теперь это упоминание Signal по ACI. Кнопка непрочитанных упоминаний, как `focusNextMention` в Web A: сообщение с непрочитанным упоминанием приходит с `mentioned` и `media_unread`, счётчик растёт с новыми сообщениями (у Web A тоже только с новыми), `messages.getUnreadMentions` отвечает новым методом провайдера `fetchUnreadMentions`; упоминание читается вместе с сообщением, поэтому `readMessageContents` и `readMentions` ничего не меняют в движке. На демо без нового упоминания кнопка не проверена. Порядок подсказок упоминаний как в Web A — порядок участников группы. Набор текста в обе стороны уже есть в адаптере (`messages.setTyping`, `updateChatTypingStatus`); на демо без второго участника не проверен.
- Реакция любым эмодзи: кнопка «ещё» у полосы реакций открывает обычную панель эмодзи с поиском.
- Общие медиа в обоих клиентах: поиск по типам `media`, `documents`, `links`, `audio`, `voice` (view once не попадает); вкладки профиля Web A теперь видны и у пользователей, Web K получает счётчики вкладок из `fetchSharedMediaCounts`. Ссылки и медиа проверены на демо (в Web K сами фото пока «Unsupported Message» до порта медиа).
- Пересылка в обоих клиентах с пределами Signal Desktop (`SelectModeActions`, `ForwardMessagesModal`): не больше 30 выбранных сообщений и 5 чатов, лишнее объясняет уведомление (проверено для чатов в обоих клиентах).
- Устройство, которое телефон отвязал (или номер зарегистрирован заново): движок стирает аккаунт и рвёт соединение, Web K выходит из слота, как `signOut` Web A, и экран привязки показывает сообщение Web A (`SignalDeviceUnlinked`, `SignalDeviceDeregistered`); причину до перезагрузки страница хранит в `sessionStorage`. На демо не проверено: `signalDev` не умеет это изображать.
- Ссылки Signal в Web K, как `openSignalLink` Web A: ссылка в сообщении (`signal.me`, `signal.group`, `signal.art`, `signal.tube`, `signal.link`, `sgnl:`) и вставленная в поиск («Open Signal link») открывают чат по ссылке username, номер — только после согласия на поиск через CDS, приглашение в группу, стикерпак, а прокси, звонок, привязка устройства и перенос аккаунта объясняются текстами Web A (основное устройство привязывает новое). Разбор ссылок общий с Web A (`@signal-app/signal-links`). Политика CSP не пускает встроенные `onclick`, поэтому щелчок по ссылке сообщения, подписи или превью Web K разбирает сам (`runContentAnchorHandler`) и выполняет только ссылки Signal, предупреждение о маскированной ссылке (в том числе ссылки Signal), хэштеги и метки времени; ссылки Telegram (`tg:`, `t.me`), команды ботов и карты показывают «This link is not supported», как и ссылка из адреса страницы, поиска или истории. Номер телефона из любой ссылки ищется только после подтверждения (`lookUpPhoneNumber`). Привязка устройства по ссылке — окно как `LinkDeviceModal` Web A: ссылка в поле, предупреждение о полном доступе, Enter не подтверждает пришедшую ссылку, ошибки по `LINK_ERROR_KEYS`; строки «Find by username» и «Open Signal link» в поиске раньше гасил обработчик списка чатов. Поиск чатов находит номер в любом написании (`+1 555 010 0001`, `(555) 010-0001`), в обоих клиентах. Проверено на демо.
- Профиль в Web K сверен с Web A (человек и группа): телефон, «о себе», номер безопасности, mute, блокировка, «Share contact», участники, описание группы, вкладки общих медиа; пункт «Report» в меню группы убран, как в Web A.
- Работает на демо-аккаунте и через туннель: экран привязки с настоящим кодом `sgnl://linkdevice`, список чатов (закрепление, непрочитанные, mute, галочки), открытие личного и группового чата с историей, отправка текста (неудачная отправка помечается), уведомления Signal (звонки, изменения группы, номер безопасности), статус соединения, переход между `/k/` и `/a/` с теми же чатами.
- Список чатов: архив и папка «Archived Chats», закрепление, mute и unmute, пометка прочитанным и непрочитанным, удаление чата, блокировка и разблокировка (`messages.toggleDialogPin`, `folders.editPeerFolders`, `account.updateNotifySettings`, `messages.markDialogUnread`, `messages.deleteHistory`, `contacts.block`/`unblock`). Папок чатов нет, как и у Web A для Signal; «Clear history», «Chat Folders» и очистка по датам в календаре чата убраны: Signal не удаляет часть чата, и адаптер отклоняет `messages.deleteHistory` с `just_clear` или датами, а не удаляет весь чат. Предел закреплённых чатов Signal (четыре) показывается одним сообщением Signal вместо окна Telegram Premium. Mute — на срок или навсегда; кнопки звука чата нет: Signal хранит только mute.
- Группы: участники с ролями (администратор, метки участников), описание и ссылка в профиле группы, создание группы (`messages.createChat`), изменения группы через провайдер (название до 32 и описание до 480 графем — их проверяет провайдер при сохранении, аватар до 3 МиБ — предел загрузки сервера групп, участники, администраторы, права, заявки, выход, таймер исчезающих сообщений).
